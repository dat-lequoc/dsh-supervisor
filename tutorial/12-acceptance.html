Part II — Build · Milestone 7

Acceptance run

The formal definition of done: one clean workspace, one scripted mission, every behavior forced once, every artifact graded, and the restart drill. Pass this twice in a row and your supervisor is real.

Why a formal acceptance at all

Chapter 10’s rehearsal proved the branches work when freshly coaxed. Acceptance proves they work from a cold start, without coaching — the difference between a demo and a system. The protocol below is your design’s M6, adjusted for the native-first build. Its exit criterion is the design’s own: every bullet passes twice in a row; when a step fails, fix persona wording first, machinery second.

Setup: a virgin workspace

Optionally open the terminal dashboard from chapter 11 against this workspace, then start a fresh main-agent session on it. From here on you speak only the scripted lines — no hints, no “remember to log that.” If you must coach, that is a finding: note it, fix the persona, restart the run.

Driving it headless (how this run was actually tested)

You can run this whole script without touching the browser: the web process exposes its RPC over plain HTTP — POST /api/<method> with an envelope {"type":"client-request","rpcId","method","payload"} (packages/host/apiproxy/src/fetch/handler.ts). Useful methods: session.create (which mount-validates the preset — it fails with agent-preset-invalid on a broken composition, an API-side alternative to standingKeyFor), session.prompt (mode: queue | steer), session.list (a running flag per session), session.history, and agentPreset.copy (the roster’s authoring write, over HTTP). The repo wraps these as tutorial/drive.py: 

S=$(python3 $HOME/src/dsh-supervisor/tutorial/drive.py create --cwd $HOME/agi-acceptance)
python3 $HOME/src/dsh-supervisor/tutorial/drive.py send  "$S" "Goal: produce SUMMARY.md … deliver."
python3 $HOME/src/dsh-supervisor/tutorial/drive.py steer "$S" "kill that worker and rescope"
python3 $HOME/src/dsh-supervisor/tutorial/drive.py tail  "$S"

The restart drill

Now the property that gives the system its name — indifference to restarts. Your supervisor’s memory is three-layered, all durable: the session log (native), .agi/ (yours), the goal tool’s state (native). Prove all three:

Test it live — restart resilience
  1. Mid-mission (re-run steps 1–2 with a fresh goal, or before step 7), return to the terminal running dsh, press Ctrl-C, wait for shutdown, then run dsh web again.
  2. Reload the browser; open the same supervisor session (it is in the sidebar — sessions are durable).
  3. Say exactly: “continue.”
  4. Expect: it re-reads .agi/ as needed, checks list_agents for its workers (durable children — a settled one’s outcome is on disk; an unfinished one can be messaged, which cold-resumes it), re-arms its check-in reminder if workers still run, and proceeds. It must not re-interview, re-write GOAL.md, or spawn a duplicate worker for work already done.
  5. Caveat to verify honestly: a schedule reminder that would have fired while the process was down is delivered per the schedule subsystem’s catch-up rules on resume. The packaged Feed and its stopped-state fold return automatically; they are not process-memory dynamic plugins.

The Full stop drill

Test the terminal operator action
  1. With a worker running and the recurring check-in armed, open Feed and click ■ Full stop (repeat once from a worker's Feed to verify root-lineage targeting).
  2. Expect the active supervisor turn to stop and every schedule reminder to disappear. Refresh: the stopped status remains. The worker itself is not killed and may settle once.
  3. Wait beyond wakeMinutes: the supervisor must not recur. Then send a direct user prompt; that explicit resume should re-arm exactly one check-in if a worker remains.

Grading and the failure ledger

Auto-grade the whole run: "$HOME/src/dsh-supervisor/tutorial/grade.sh" m7 — it re-runs the milestone-2 through 5 graders against $HOME/agi-acceptance, then checks the acceptance-specific evidence (the restart resume marker in the supervisor’s log, the post-completion amendment). Steps only a human can judge are printed as MANUAL reminders.

Keep an acceptance ledger (a file in $HOME/src/dsh-supervisor/, next to the design): one line per step per run — pass / fail(reason) / coached(what). The design’s exit criterion, verbatim: every bullet passes twice in a row. Common first-run findings and their fixes:

Where you stand

Passing this chapter means you have what the design document calls the headless core — goal goal setup, delegation, supervision, questions, files, resilience — built from a preset, a persona, one schedule row, narrow bundled policy plugins, and a file convention. The 24/7 mission is now “run start a bigger goal and let it loop,” plus whatever worker tooling that mission needs — which workers install themselves at runtime, per their tasks.

What remains optional: the custom machinery the plan originally front-loaded. If you want it — structured traces, a blocking wait, or mission-specific UI beyond the shipped Feed — chapter 13 shows the packaged-plugin path with a real installed example as your template.
