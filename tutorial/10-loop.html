The supervision loop

Everything assembles here. The supervisor now runs the full cycle unattended: spawn → sleep → wake (settle / report / timer / you) → triage → repeat — with every action logged. You force each branch once and watch it hold.

The loop, restated as wake sources

Inspection without a trace plugin

The timer-wake rule says “inspect the worker.” Give the supervisor a concrete, cheap way to do that. Two native surfaces:

  1. list_agents — is its driver still open? This is liveness only, never evidence of useful progress.
  2. The child’s session log on disk. The child id names its directory under /root/.dsh/sessions/--root-agi-lab--/, and the JSONL is grep-friendly. The last few tool/call lines answer “what is it doing right now” in one command.

Field note: idle workers are a resource, not a corpse

Observed live: given an amendment after a worker settled, the supervisor did not spawn a fresh worker — it reasoned “idle, not dead — a send_message starts its next turn” and reused the settled worker with its context intact (chapter 9’s cold-resume semantics, applied spontaneously). That is legitimate and often better: the worker already holds the grounding for its deliverable. Let the supervisor make this call; only force a fresh spawn when the old context is poisoned — which is what the kill verb is for.

The full-loop rehearsal

Now run a real, multi-worker mission and force every branch. Use a goal small enough to finish in one sitting but big enough to need two workers. The script below is your design’s M6 acceptance, minus the pieces you moved to chapter 12.

Test it live — milestone 5 acceptance: one mission, every branch

Auto-grade after the mission: python3 /root/dev/tests/grade.py m5 — grades the CHANGELOG verb coverage, the assumption, NOTES verdicts, the progress feed, the deliverable, worker count, and timer hygiene.

Setup: fresh main-agent session in /root/agi-lab; config.json: wakeMinutes: 5, questionWaitMinutes: 2.

  1. Goal setup: mission — “Produce SUMMARY.md describing the layout of /root/deepseek-harness/docs — delegate the work, supervise, deliver.” Expect get_goal → workspace inspection → start_goal/GOAL.md → same-turn work. (Deliberately omit where SUMMARY.md should go — seed for step 4.)
  2. Spawn + timer: expect a guarded subagent call with an explicit allowed model and a complete task prompt (Role/Objective/Scope/Context/Protocol/Constraints — read the tool call in the UI and grade it), a spawn line in CHANGELOG, and a recurring check-in created.
  3. Timer wake with a verdict: when the 5-minute reminder fires while the worker runs, expect: list_agents + a log/artifact comparison + a concrete checkpoint in NOTES.md. If unchanged, expect an immediate status probe; if still unchanged at the following check, expect interrupt and recovery rather than another monitoring-only verdict.
  4. Unanswered question: at some point the output-location ambiguity should surface (the worker reports, or the supervisor asks you). Stay silent. Expect: pending → patience reminder → assumed with a sensible recorded assumption → work continues.
  5. Forced steer: while a worker runs, say — “have it also count the .zh.md files.” Expect send_message to join at the worker's next model step (not a kill, not a respawn) + a steer CHANGELOG line.
  6. Forced kill: say — “that worker’s approach is wrong; kill it and respawn with a tighter scope.” Expect interrupt_agent + kill line + a fresh spawn whose task visibly narrowed.
  7. Settle → next unit: when a worker settles, expect: outcome.md read, progress.jsonl line, and either the next spawn or goal completion — without you prompting.
  8. Finish: SUMMARY.md exists where the assumption said; goal marked complete; the check-in reminder deleted (schedule_list shows none).

Grade the artifacts, not the vibes: at the end, cat .agi/CHANGELOG.jsonl should read as a faithful diary of steps 2–7. If an action happened without its line, tighten the persona’s STATE section and re-run — the changelog’s completeness is what makes the 24/7 version auditable.

Restart resilience (the cheap version)

The full restart test belongs to chapter 12, but do the cheap half now: close the browser tab, reopen the session, and say “continue.” Expect the supervisor to pick up from its files and the goal tool — no re-interviewing, no lost workers (they are durable sessions; list_agents still sees them).

Why persona iteration is the real work of this chapter

Every failure you see in the rehearsal is one of three kinds: a protocol gap (the persona never said what to do — add a rule), a protocol violation (it said so, but the model skipped it — strengthen the wording, move it earlier, or make it a numbered step), or a mechanism failure (a tool errored — re-validate the preset/bundle and run its tests). Fix in that order. Native lifecycle machinery and the bundle's narrow policy frontends are separately testable; behavioral debugging still has a durable paper trail.
