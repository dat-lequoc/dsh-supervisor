Failure catalog

N row(s) did not activate: waiting for <service>Consumer row inside the wrong realm, or a host service that genuinely isn’t mounted (e.g. you referenced schedule before chapter 8).

Dynamic-plugin problems (chapter 5 and chapter 11's historical exercise)

SymptomLikely cause → fix
service "x" is not declaredctx.x without inject. Use ctx.get('x') + undefined check, or declare the hard dependency.
Client half parse failureJSX / TypeScript / import in dynamic code. Plain JS, React.createElement only.
Run “succeeded” but no UI appearedRendering happens after the run answers. cordis_inspect_self(pluginId, packageId) → renderFailure carries the crash for the exact run.

Supervisor-behavior problems (chapters 7, 10, 12)

SymptomClass → fix
Starts a goal without inspecting existing scriptsProtocol violation → strengthen GOAL SETUP so durable state and relevant runbooks/scripts are read before start_goal.
Blocks forever on a questionCheck chapter 8’s patience path actually works (reminder created? schedule mounted?), then strengthen QUESTIONS wording.
Worker calls ask_user_question and waits silentlySpawn-policy regression: the guarded request must deny that tool; report remains the sole upward question channel.
Repeats “still running” on every timer wakeProtocol violation: running is driver liveness only. Compare concrete evidence; first unchanged check probes, the next interrupts and recovers/respawns.
Steers healthy workers on every timer wakeProtocol gap → define fresh evidence concretely and prescribe recording the checkpoint without gratuitous steering.
Kills where a steer would doPersona: “interrupt_agent first ONLY if the current turn must stop now” — move it adjacent to the steer rule; models read locally.
Worker spawn rejects reasoning effortThe exact selected model does not advertise that route's configured fixed effort. Choose a supported catalog id on the model row or provider/default; the plugin never clamps.
Settle notice is generic after a failed requestIntermediate failures are intentionally silent during native retries. Only an exhausted final error gains Terminal failure [CODE]; a successful retry settles normally.
Native stop square “didn't stick”It aborts one turn, not durable reminders. Use Feed's ■ Full stop; it deletes reminders after the agent is idle and persists the stopped fold.
CHANGELOG has gapsFuse logging into each verb’s sentence (“Steer = send_message + one CHANGELOG line, always together”).
After restart it re-interviewsIt didn’t consult .agi//goal state — check GOAL.md exists and the goal tool shows the goal; if yes, strengthen STATE’s “restart must cost nothing.”
Duplicate workers for done workOutcome discipline: settle-notice triage must read outcome.md before planning; make step 4’s first bullet explicit.

Where you are, and what’s next

You built an always-on supervisor out of one authored preset, protocol prose, one schedule row, narrow bundled policy/UI plugins, and a file convention — and you can explain every mechanism it stands on: the plugin tree, the two planes, the inbox, the continuable child, the settle notice. That understanding is the durable artifact; the supervisor is just its first proof.

Natural next steps, in rough order of ambition:

  • Raise the parallel limit — the persona’s one-worker rule is a sentence; the machinery already handles many children (interleaved settle notices and all). Try two.
  • Give workers richer capabilities per task — the spawn row supports a settings-approved image-capable route can inspect screenshots, while the fixed supervisor filter keeps ask_user_question out of every worker.
  • Run the real mission — non-blocking goal setup scales to “grow this X.com account”; credentials are requested only when the existing workspace setup cannot supply them safely.
  • Self-evolution (design §3.4) — let the supervisor propose persona diffs as questions, applied by you. Ordinary chat remains the steering and stop surface.
  • Contribute upstream — you found the stale skill (chapter 5). The repo takes issues and discussions; CONTRIBUTING.md is short.
